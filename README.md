# Prompt Lens

Расширение Chrome. Наводишь курсор на любую картинку в вебе — всплывает пилюля
`prompt`. Клик — и через несколько секунд готов промпт, по которому эту картинку
можно повторить в Nano Banana или GPT Image 2.

Не подпись к фотографии, а бриф: сюжет, свет, оптика, палитра, материалы —
разобранные по слоям и собранные в связную английскую прозу. Без тег-супа,
без `--ar`, без негативных промптов: целевые модели их не понимают.

Техзадание — [`files/SPEC.md`](files/SPEC.md), инструкция анализатора —
[`files/analyzer-prompt.md`](files/analyzer-prompt.md).

---

## Установка

1. `chrome://extensions` → включить «Режим разработчика».
2. «Загрузить распакованное расширение» → выбрать эту папку.
3. Открыть настройки расширения и вставить ключ Gemini из
   [AI Studio](https://aistudio.google.com/apikey).
4. Нажать «Проверить»: скажет, рабочий ли ключ и есть ли для него указанная модель.

Сборки нет — ни npm, ни бандлера. Папка грузится как есть.

Модель по умолчанию — `gemini-3.6-flash`, id правится в настройках. Если ключ её
не отдаёт, «Проверить» покажет список доступных flash-моделей.

## Как пользоваться

| Действие | Что делает |
|---|---|
| Навести на картинку | Пилюля `prompt` в левом верхнем углу. Всё меньше 140px игнорируется |
| `Alt+P` | Разбор картинки под курсором — для сайтов, где hover перехвачен лайтбоксом |
| `Alt` + растянуть рамку | Разбор только выделенного фрагмента — для коллажей и мудбордов |
| Клик по иконке расширения | История |
| `Esc` | Закрыть карточку |

**Карточка.** Промпт, счётчик слов, теги эстетики, пропорции кадра, палитра
плашками (клик копирует hex). Два переключателя: целевой генератор
(Nano Banana / GPT Image 2 / Universal) и режим — «Повторить» или «Только стиль»,
где сюжет заменён плейсхолдером `{{SUBJECT}}`.

**Разбор по слоям — главное.** Поля редактируемые: правишь «свет» — и промпт
пересобирается. Обычно промпт нужен не один в один, а «вот это, но вечерний свет
вместо дневного». Пересборка идёт текстовым запросом из готового JSON, картинка
второй раз не улетает — это примерно 80% экономии токенов, и работает мгновенно.
Смена генератора устроена так же.

**История.** Поиск по промптам и тегам, фильтры по избранному, генератору и датам,
свои заметки к записи, ссылка на страницу-источник. Экспорт: JSON по текущему
фильтру или markdown-подборка избранного. Сравнение двух записей — модель
объясняет разницу по слоям и выдаёт промпт-дельту: что дописать к первому,
чтобы получить второе.

**Кэш.** Одна картинка не разбирается дважды: в карточке пометка «из кэша» и
кнопка перегенерации рядом.

## Раскладка

```
manifest.json
background.js      сервис-воркер: сеть, Gemini, кэш, запись истории
content.js         пилюля на картинках и карточка результата, всё в Shadow DOM
lib/prompt.js      инструкция анализатора, сборка запросов, разбор ответа
lib/store.js       обёртка над chrome.storage: настройки, история, кэш, расход
history.html/js    страница истории
options.html/js    ключ, модель, генератор, шаблон инструкции
page.css           общие стили страниц
icons/             иконки, генерируются scripts/icons.mjs
dev/               стенд: гоняет карточку и историю в обычной вкладке
files/             ТЗ и инструкция анализатора
```

`content.css` не нужен: стили живут внутри Shadow DOM в `content.js`. Стили
сайтов-доноров агрессивные, без изоляции карточку разносит.

## Стенд

Расширение можно посмотреть без установки и без ключа: `dev/stub.js` подменяет
`chrome.*` и отдаёт готовый разбор, а `dev/preview.html` подтягивает настоящие
`content.js` и `history.js`.

```bash
python3 -m http.server 4173
```

Дальше `http://localhost:4173/dev/preview.html?view=card` — карточка на демо-картинках,
`?view=history` — история на шести записях. Разметку истории стенд берёт из самой
`history.html`, чтобы не разъезжаться с ней.

Иконки пересобираются так:

```bash
node scripts/icons.mjs
```

PNG собирается руками через `zlib` — Chrome не принимает SVG в иконках, а тащить
графический пакет ради четырёх картинок незачем.

## Что стоит знать, если будешь править

**`[hidden]` перебивается классом.** У `.pill` и `.card` задан `display`, а он
сильнее правила браузера для `[hidden]`. Без явного `[hidden] { display: none
!important }` карточка видна с самого старта. Та же строка есть в `page.css`.

**`IntersectionObserver` не видит `display: none`.** Превью в истории грузятся
лениво, и наблюдать надо за рамкой `.item__shot`, а не за скрытой картинкой
внутри: у скрытого элемента нет бокса, и обсервер про него молчит.

**Картинка ищется по всему стеку под курсором.** `elementFromPoint` на Pinterest
и Dribbble возвращает прозрачный оверлей, а не превью. Поэтому
`elementsFromPoint` и проход по списку; `html` и `body` пропускаются, иначе
фон сайта считался бы референсом.

**Превью подменяется на оригинал.** Pinterest отдаёт `/236x/`, Behance —
`project_modules/<размер>/`, у Dribbble размер живёт в query. Контент-скрипт
собирает список кандидатов по убыванию качества, воркер идёт по нему сверху вниз
и откатывается на исходную ссылку. Чем крупнее исходник, тем точнее разбор.

**Если картинку не отдают вообще** (CORS, 403), воркер снимает видимую область
вкладки и вырезает из неё место картинки. Поэтому разбор работает даже там,
где прямая ссылка закрыта.

**Ключ только в `storage.local`.** В `storage.sync` он уехал бы в облако Google
вместе с настройками профиля.

**Превью истории лежат отдельными ключами** `thumb:<id>`, а не внутри массива
записей: иначе каждое нажатие звёздочки переписывало бы несколько мегабайт
base64. История режется на 300 записях, вытесняется самая старая незвёздная.

## Границы

Это личный инструмент на одного человека. В Chrome Web Store такое не публикуют:
ключ пользователя лежит в клиенте, для магазина нужен свой прокси. Аккаунтов,
оплаты и облачной синхронизации здесь нет и не планируется.

Расход считается в настройках — все обращения к модели за сутки: разбор картинки,
пересборка промпта, сравнение. Бесплатный тариф Flash — порядка 1500 запросов
в сутки.

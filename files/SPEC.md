# Prompt Lens — техническое задание

Расширение Chrome. Наводишь курсор на любую картинку в вебе — всплывает кнопка.
Клик — и через несколько секунд у тебя готовый промпт, по которому эту картинку
можно повторить в Nano Banana или GPT Image 2.

Целевой пользователь — один человек: дизайнер, который собирает референсы
на Pinterest и генерит в Nano Banana и GPT Image 2. Не Midjourney, не Stable
Diffusion. Это решение определяет всё остальное: промпты пишутся связной прозой,
без тег-супа, без `--ar`, без негативных промптов.

---

## 1. Стек и ограничения

- Manifest V3, чистый JS без сборщика. Никаких npm-зависимостей и бандлеров —
  папка должна грузиться в `chrome://extensions` как есть.
- Весь UI внутри страницы живёт в Shadow DOM. Стили сайтов-доноров
  (Pinterest, Behance, Dribbble) агрессивные, без изоляции всё поедет.
- Модель: Gemini через `generativelanguage.googleapis.com/v1beta`, ключ
  из AI Studio, лежит в `chrome.storage.local`.
- Модель по умолчанию `gemini-3.6-flash`, id редактируется в настройках.
- `unlimitedStorage` в permissions — история с превью упрётся в 5 МБ иначе.

---

## 2. Структура файлов

```
manifest.json
background.js        сервис-воркер: сеть, Gemini, кэш, запись истории
content.js           хендл на картинках, карточка результата
content.css          не нужен — стили внутри Shadow DOM в content.js
lib/prompt.js        сборка инструкции анализатора, парсинг JSON-ответа
lib/store.js         обёртка над chrome.storage: настройки, история, кэш
history.html/js      отдельная страница истории
options.html/js      ключ, модель, целевой генератор, шаблон инструкции
```

---

## 3. Поток работы

1. `content.js` слушает `mouseover` на `document`. Находит ближайший `<img>`.
   Отсекает всё меньше 140×140 и всё, что не `http(s)`.
2. У картинки под курсором в левом верхнем углу появляется пилюля `prompt`.
   Пилюля держится, пока курсор на картинке или на самой пилюле.
3. Клик → `content.js` шлёт в воркер `{type: 'ANALYZE', url, pageUrl, target}`.
4. Воркер проверяет кэш по хэшу URL. Есть попадание — отдаёт мгновенно,
   помечает `fromCache: true`.
5. Промах — качает картинку, ужимает до 1024px по длинной стороне через
   `OffscreenCanvas`, кодирует в base64.
6. Шлёт в Gemini картинку + инструкцию анализатора с подставленной целевой
   моделью. Парсит JSON.
7. Кладёт в кэш и в историю (вместе с превью 256px webp), отдаёт в контент.
8. Карточка раскрывается и показывает результат.

**Обработка ошибок.** Нет ключа → карточка со ссылкой на настройки. 429 →
«Лимит исчерпан, подожди минуту». Битый JSON от модели → один автоматический
повтор с припиской «верни строго JSON», потом честная ошибка с сырым текстом
под спойлером. Картинка не скачалась (CORS, 403) → предложить хоткей на
скриншот области как запасной путь.

## 4. Функциональность

### 4.1 Ядро

- **Пилюля по наведению.** Появляется на картинках от 140px.
- **Хоткей `Alt+P`** — анализ картинки под курсором. Нужен для сайтов, где
  hover перехвачен лайтбоксом или картинка лежит в `background-image`.
- **Поддержка `background-image`.** Часть сайтов не использует `<img>`.
  Проверять `getComputedStyle(el).backgroundImage` у элемента под курсором.
- **Подмена превью на оригинал.** Pinterest отдаёт `/236x/`, Behance и
  Dribbble — свои суффиксы размера. Пробовать оригинал, откатываться назад.
  Чем крупнее исходник, тем точнее разбор.

### 4.2 Карточка результата

Позиция — фиксированная, правый нижний угол, ширина 400px. Состояния:
свёрнута до заголовка / развёрнута / загрузка / ошибка.

Содержимое сверху вниз:

- Шапка: имя, версия, кнопка сворачивания.
- Заголовок `PROMPT`, рядом счётчик слов, кнопка перехода в историю.
- Тело промпта. Моноширинный, выделяемый, скроллится.
- Ряд тегов эстетики из поля `tags`.
- Переключатель целевого генератора: `Nano Banana` / `GPT Image 2` / `Universal`.
  Переключение не шлёт картинку заново — уходит дешёвый текстовый запрос
  с готовым разбором (см. analyzer-prompt.md).
- Переключатель режима: `Повторить` / `Только стиль`. Второй показывает
  `prompt_style_only` с плейсхолдером `{{SUBJECT}}`.
- Кнопка `Копировать`.

### 4.3 Разбор по слоям

Под промптом — сворачиваемая секция с полями разбора: сюжет, сцена,
композиция, свет, оптика, палитра, материалы, стиль, настроение.

**Поля редактируемые.** Правишь «свет» — промпт пересобирается. Пересборка
идёт текстовым запросом из готового JSON, картинка не отправляется.
Это главная фича: обычно промпт нужен не один в один, а «вот это, но
вечерний свет вместо дневного».

Палитра рисуется полосой цветных плашек. Клик по плашке копирует hex —
пригодится и вне генерации.

### 4.4 История

Отдельная страница, открывается из карточки и из иконки расширения.

- Сетка карточек: превью, промпт, теги, дата, домен-источник.
- Поиск по тексту промпта и тегам.
- Фильтры: избранное, целевой генератор, диапазон дат.
- Звёздочка «в избранное».
- Свои заметки к записи — что получилось при генерации, что подкрутить.
- Ссылка на страницу-источник.
- Экспорт: JSON целиком или markdown-подборка избранного.
- Удаление записи и очистка всей истории.

### 4.5 Правки и референсы

Клик по пилюле открывает меню, а не шлёт запрос сразу: выбор целевого
генератора, строка «что изменить в кадре», плюс для картинок-референсов.
Пусто — обычный разбор. `Alt+P` остаётся быстрым путём без меню.

- **Правка применяется к разбору**, а не дописывается к готовому промпту:
  дописанная фраза садится в самое слабое место текста. Меняются только
  затронутые слои; носитель, эпоха, сборка, свет, оптика и обработка остаются
  прежними, и вставка не выглядит чище остального кадра. Промпт описывает
  результат, а не разницу с оригиналом.
- **Референсы** — до четырёх картинок, файлом, из буфера или перетаскиванием.
  Каждая подписывается отдельно, подпись уходит частью запроса прямо перед
  своей картинкой. Генератор референс не увидит, поэтому внешность выписывается
  словами, а всё исполнение референса выбрасывается — оно берётся из кадра.
- Правка и подписи едут в историю и в поиск по ней; сами картинки не хранятся.
- Ключ кэша учитывает правку и референсы.

### 4.6 Рекомендации

Промпт — текст, и часть вещей текстом не передаётся: конкретное лицо, точный
логотип, читаемая надпись. Модель возвращает `hints` — короткий список того,
что придётся доложить в сам генератор руками. Под промптом он рисуется рядом
зелёных плашек, выше тегов эстетики.

- Шесть видов: `person`, `object`, `logo`, `text`, `setting`, `note`. Вид виден
  значком, а не цветом — акцент в расширении один и работает на состоянии.
- `text` до 6 слов на плашке, `why` одним предложением в подсказке.
- Не больше четырёх; пустой список — нормальный ответ. Общие советы вида
  «поэкспериментируй с настройками» инструкция запрещает: избыток бесполезных
  рекомендаций обесценивает полезные.
- Живут в `analysis`, поэтому переживают смену генератора и правку слоёв,
  но в запрос на пересборку не уходят: это вывод, а не вход.

### 4.7 Полезные мелочи

- **Кэш по URL.** Одна картинка не анализируется дважды. В карточке пометка,
  что результат из кэша, рядом кнопка «Перегенерировать».
- **Анализ фрагмента.** Зажал `Alt` и растянул рамку по картинке — уходит
  только выделенная область. Для плотных коллажей и мудбордов незаменимо.
- **Сравнение двух картинок.** Отмечаешь две записи в истории → модель
  объясняет разницу и выдаёт промпт-дельту: что дописать к первому, чтобы
  получить второе. Отличный инструмент для итераций.
- **Пропорции.** Модель возвращает `aspect_ratio` — показывать явно,
  чтобы не забыть выставить в генераторе.
- **Счётчик расхода.** В настройках — сколько запросов ушло сегодня.
  Бесплатный тариф Flash это порядка 1500 в сутки, но знать полезно.

## 5. Дизайн

Референс — скриншот PromptCard, приложен отдельно. Берём паттерн, а не копию.

**Направление.** Тёмная стеклянная карточка, лежащая поверх чужого сайта.
Она не должна выглядеть как часть Pinterest — наоборот, как прибор, который
ты на страницу принёс. Инструментальная, техничная, спокойная.

**Токены:**

```
--bg        #0C0C0E   корпус карточки
--surface   #16161A   поля, кнопки
--line      #26262B   границы
--text      #E8E6E1   основной текст
--muted     #8A8A93   подписи, служебное
--accent    #7DD3A0   готовность, фокус, активное состояние
--warn      #FF9D8A   ошибки
```

Акцент один и работает только на состоянии — не на украшении. Ошибка красится
в `--warn` и объясняет, что делать, а не извиняется.

**Типографика.** Интерфейс и промпт — моноширинный (`ui-monospace`,
системный). Промпт это код для генератора, он и должен выглядеть кодом.
Служебные подписи — верхний регистр, размер 11px, трекинг 0.12em.
Заголовок `PROMPT` крупный и жирный, это точка входа взгляда.

**Форма.** Радиус 14px у карточки, 8px у полей, 999px у пилюли.
Границы в один пиксель, без теней внутри карточки. Внешняя тень одна и
глубокая — карточка должна читаться поверх любой подложки.

**Движение.** Три места, больше не нужно: появление пилюли (12мс сдвиг вверх
на hover), пульсация точки во время запроса, раскрытие карточки. Всё остальное
статично. `prefers-reduced-motion` уважается.

**Сигнатурный элемент** — та самая точка слева в пилюле. Зелёная в покое,
пульсирует во время запроса, краснеет на ошибке. Один индикатор состояния
на всё расширение, без спиннеров и прогресс-баров.

**Обязательный минимум качества:** видимый фокус с клавиатуры, вся карточка
проходится табом, `Esc` закрывает, карточка не вылезает за вьюпорт на
маленьких окнах.

## 6. Модель данных

```js
// chrome.storage.local
{
  settings: {
    apiKey: "",
    model: "gemini-3.6-flash",
    target: "nano-banana",     // nano-banana | gpt-image-2 | universal
    template: "...",           // инструкция анализатора, редактируемая
    minImageSize: 140
  },

  history: [{
    id: "uuid",
    createdAt: 1770000000000,
    sourceUrl: "https://...",     // сама картинка
    pageUrl: "https://...",       // где нашёл
    thumb: "data:image/webp;base64,...",   // 256px
    tweak: {                      // null, если разбирали без правок
      edit: "вместо яблока банан",
      refs: [{ caption: "мужчина слева, по пояс", name: "man.jpg" }]  // без картинок
    },
    analysis: { /* JSON из analyzer-prompt.md */ },
    prompts: {
      "nano-banana": { replicate: "...", styleOnly: "..." },
      "gpt-image-2": { replicate: "...", styleOnly: "..." }
    },
    tags: [],
    starred: false,
    note: ""
  }],

  cache: { "<sha1 от url>": { id: "...", createdAt: 0 } },

  usage: { "2026-08-13": 14 }
}
```

История режется на 300 записях, вытесняется самая старая незвёздная.

## 7. Порядок работ

1. Каркас: манифест, воркер, пилюля по наведению, один запрос в Gemini,
   вывод сырого текста в карточку. Проверить на Pinterest, Behance, Google Images.
2. JSON-контракт: инструкция анализатора, парсинг, повтор при битом JSON,
   карточка с полями разбора.
3. Дизайн карточки по разделу 5, состояния, клавиатура.
4. Переключатели целевого генератора и режима, пересборка без картинки.
5. История, кэш, страница истории с поиском и экспортом.
6. Редактируемые слоты разбора.
7. Хоткей, `background-image`, выделение фрагмента.
8. Сравнение двух записей.

Каждый пункт — рабочее состояние, которое можно поставить и потрогать.
Не уходи в следующий, пока предыдущий не проверен вживую на реальном сайте.

## 8. Что не делать

- Не тащить фреймворки и сборку. Расширение на четыре экрана, ванильного JS хватает.
- Не хранить ключ в `storage.sync` — уедет в облако Google вместе с настройками.
- Не публиковать в Web Store в таком виде: там ключ пользователя в клиенте
  недопустим, нужен свой прокси. Пока это личный инструмент — нормально.
- Не добавлять аккаунты, оплату, облачную синхронизацию. Это утилита на одного.
- Не генерить негативные промпты и параметры вида `--ar 3:4`. Целевые модели
  их не понимают, а мусор в промпте портит результат.
